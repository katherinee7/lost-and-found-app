# P3 progress

## Milestone 1: Saved found records

Finder search now offers **Save for later**. It saves the current category,
colors, brand, possible loss-time interval, and locations as a private found
record, titled from its category. Searching first is optional.

Open **My Reports → Saved found records** to review the saved characteristics
or close a record. Closed records stay in that list. Missing reports have a
separate list, and existing P2 records without a kind still behave as missing.
No database migration is needed.

Authorship always comes from the authenticated session. Found records cannot
appear in potential-owner search or be used to start a conversation, even by
someone who knows their report ID. Concepts remain independent: Reports
compositions authenticate, create/register, and close/remove through sync-engine.
Matching remains unchanged; ItemReporting only supplies search summaries for
open missing reports.

The generated typed contract now includes kind on creation and own-list results.
Deploy the frontend and backend together; new create requests must supply kind.

Automated tests cover found creation, private listing, forged-author requests,
unauthorized closes, persistence across assembly instances, search exclusion,
invalid requests with unchanged state, closing, and the legacy missing schema.
They run in temporary databases and never migrate or reset application data.

Run from the repository root with local MongoDB available:

```sh
bun run --cwd app test
bun run check
bun run type-check
bun run build
```

See [saved test output](app/tests/results/saved-found-records.txt).
Interactive browser checks still to perform: save an item without searching;
review all its fields in My Reports; sign in as another user and check privacy;
close the saved record and reload. The assembled HTTP tests exercise the backend
for these operations; they do not automate browser clicks.

## Milestone 2: Later matches and counts

Each open found record in My Reports now shows its current potential-match
count. **View matches** expands limited summaries and offers **Contact owner**,
which opens Messages. **Refresh records and matches** reloads records and
recalculates their results. Loading My Reports also calculates them. Closed
found records do not show match counts or actions. A failed lookup shows an
error rather than an incorrect zero count.

`Reports.Matches` authenticates the session, calls `ItemReporting.readFound` to
require an open found record belonging to that user, and passes its stored
attributes to the shared SearchResults former. Matching supplies compatible
record IDs using its existing rules; ItemReporting supplies limited summaries
only for other users' open missing reports. Finder search now excludes the
finder's own missing reports too. Attributes supplied by callers cannot replace
the found record's stored characteristics. Existing reports without kind still
participate as missing reports.

The frontend derives each count from the returned list length; no counters or
pairs are persisted. There is no background polling, unread state, or
notification behavior. Counts are a snapshot at the last load/refresh.

All 31 tests passed, including the operational sequence save found → load zero
matches → another user submits missing → load one match → owner closes missing
→ load zero matches. Tests also cover each incompatible characteristic,
self-authored and legacy reports, closed and non-found targets, unauthorized
requests, forged authorship, limited summaries, and contact from a result.
See [saved execution output](app/tests/results/later-matches.txt).

Manual browser checks still to perform: use two accounts to save a found record
and then create a compatible missing report; refresh the saved records and
verify the count and View matches; contact the owner; close the missing report
and refresh to verify the count decreases. Automated tests exercise the assembled
HTTP application, not browser interactions.

## Milestone 3: Edit reports

Authors can select **Edit** on an open missing report or saved found record.
A shared form is prefilled with its title and all characteristics, with times
shown in the browser's local timezone. **Save changes** updates the record and
refreshes the list and saved-found results. **Cancel** discards the draft.
Closed records have no Edit action and remain read-only. Kind and author cannot
be changed. Existing P2 records without kind remain editable as missing reports.

`Reports.Update` derives the author from the session and calls
`ItemReporting.update`. Content validation uses the same rules and whitespace
normalization as creation. A single database update requires the record ID,
author, and open status before replacing title and attributes. Rejections leave
the report unchanged. Only after a successful update does the composition call
`Matching.register` to replace its entry, then respond. Concepts do not call
one another. The next search or saved-record refresh uses the new attributes.

A separate draft prevents unsaved changes from changing displayed records.
Unchanged time fields retain their original instants, including seconds and
milliseconds and ambiguous daylight-saving times. A refresh failure after a
successful save is reported separately from a rejected save.

All 38 tests passed (216 assertions) with `TZ=America/New_York`, covering
updates for both kinds, repeat edits, legacy compatibility, ownership,
unauthenticated requests, invalid edits with unchanged reporting/matching data,
closed restrictions, edits adding/removing matches, and form date/draft handling.
See [saved output](app/tests/results/edit-reports.txt). Backend/specification/
artifact checks, Vue type checking, and production build are also required.

Manual browser checks still to perform: edit each kind, verify every prefilled
field, cancel a draft and confirm no change, save and reload, check counts and
search with another account, and confirm closed reports have no Edit action.
The automated tests exercise concepts, assembled HTTP endpoints, and form
conversion helpers; they do not automate browser clicks.

Conversation reuse is subsequent work. Points and joint return confirmation
remain deferred; authors close their own reports and records.
